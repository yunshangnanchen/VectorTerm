# 5. 光标尾迹动画(核心特性)

对标 Kitty 的实现(`kitty/cursor_trail.c` + `kitty/shaders/trail.slang`)。这里只描述**移动时的尾迹**;
静止那块光标的形状、长宽、闪烁(周期 / 占空比 / 淡出 / 空心描边)与常驻动画
(尺寸脉冲 / 透明度呼吸)是另一组 `cursor.*` 配置,见 [手册 §10.5](config-manual.md#105-光标本体自定义)。
两组可以同时开,本体动画只改显示列表,不影响尾迹的角点积分。

先澄清一个常见误解:Kitty 的尾迹**不是**一串渐隐的光标方块,也**不是**让光标块平滑滑行,而是:

- **光标本体立即出现在目标位置**(不滑行);
- **尾迹是一个被拉伸/剪切的半透明四边形**:光标矩形的 4 个角各自以指数速度追赶自己的目标角;
- 追赶速度按"角与移动方向的夹角"逐角变化:运动**前方**的角衰减快(迅速归位),**后方**的角衰减慢(被拉长成尾巴);
- 用纯色 × 不透明度填充,并把**当前光标矩形区域挖空**(`opacity *= 1 - in_cursor_rect`),由光标本体保持清晰;
- 触发门:光标必须在某个位置**静止 ≥ N 毫秒**后,尾迹才允许跟随(`cursor_trail` 是毫秒,不是距离);位移小于阈值(默认每轴 2 格)时直接吸附,不产生尾迹 —— 这样复杂应用快速刷新 UI 时不会出现杂乱拖影。

参数(与 Kitty 对齐):

| 配置 | Kitty 名称 | 默认 | 含义 |
|---|---|---|---|
| `trail` | `cursor_trail` | `20` | 静止多少毫秒后尾迹开始跟随;`0` = 关闭;`true/false` 兼容旧配置 |
| `trail_start_threshold` | `cursor_trail_start_threshold` | `0` | 每轴最小位移(格),两轴都低于阈值时直接吸附。本项目默认 `0` = 每次移动都拖尾;设为 `2` 即 kitty 默认(单格移动不拖尾) |
| `trail_decay` | `cursor_trail_decay` | `"0.1 0.4"` | (最快, 最慢)衰减时间(秒):角追赶到 1/1024 距离所需时间 |
| `trail_max` | — (本项目扩展) | `220` | 单段动画的硬上限(毫秒);到点直接吸附。`0` = 不限制。连续输入时尾迹另有"最多 1 格"的长度钳制,松手(KeyUp)当帧收尾,`40ms` 兜底 |
| `trail_color` | `cursor_trail_color` | 跟随光标色 | 尾迹颜色 |

每帧算法(实现见 `src/cursor.rs`):

```text
dt = now - updated_at
if 光标矩形变化: pending = 新矩形; last_change = now; burst += 1     # 只记最新目标,不排队
burst *= exp(-dt / 0.35)                                            # 松手后自然回落

if now - last_change ≥ trail(ms)
   或 burst ≥ 2 (连续输入,立刻重定向)
   或 (burst ≥ 2.5 且 now - last_retarget ≥ max(dwell*3, 50ms) ≤ 120ms):
        edge = pending                                              # 重定向(覆盖,不入队)
        if burst ≥ 2.5: was_dense = true                            # 记住这次是密集输入

if 本段动画已持续 ≥ trail_max: corners = edge; 结束                  # 硬上限
else 对 4 个角:
    dist_cells = max(剩余 |dx|/cell_w, 剩余 |dy|/cell_h)
    speedup    ← 1 + 1.0·max(burst-1, 0) + min(0.45·dist_cells, 3.5)    # 封顶 12x,平滑逼近
    d      = target_corner - corner
    dot    = d · (target_corner - cursor_center) / (diag/2) / |d|
    decay  = lerp(decay_slow, decay_fast, (dot-min)/(max-min)) / speedup
    corner += d * (1 - 2^(-10·dt/decay))

if burst ≥ 2: 四个角等比收缩,使最大落后 ≤ 1 格                        # 尾迹长度硬上限
if was_dense 且 (KeyUp 或 now - last_change ≥ 40ms): corners = edge     # 松手即结束
opacity  += / -= dt / (decay_slow / speedup)                         # 随光标可见性淡入/淡出
needs_render = 任一角距目标 ≥ 0.5px
```

## 连续输入:只有一个动画,而且有上限

按住回车时终端以 ~30Hz 输出换行,光标每 33ms 下移一行。如果按"每次移动生成一个动画"的思路实现,这些动画就会排队,逐个播完才轮到下一个 —— 表现为光标后面拖着一长串旧动画、完全跟不上手。这里的处理参考 kitty 的状态驱动思路,并补上现代终端常用的限速:

1. **重定向,不排队**:动画目标始终只有一个,新位置直接覆盖旧目标(`edge = pending`),中间位置从不入队,并发动画数恒为 1;
2. **连续输入立即重定向**:`burst ≥ 2` 时跳过 dwell,不再让"已结算目标"落后真实光标一行;
3. **积压感知加速**:连续重定向累积 `burst`(封顶 12),把衰减时间常数按倍率缩短;输入越密追得越快,松手后按 0.35s 时间常数平滑回落,不会突然变硬;
4. **距离自适应**:长距离跳跃按剩余格数额外加速,避免固定 decay 在几十行位移上拖出一秒多的尾巴;
5. **尾迹长度硬钳制**:`burst ≥ 2` 时四角等比收缩到最多 1 格,不管积压多少,视觉上尾迹都不超过一行;
6. **松手即结束**:收到按键抬起(KeyUp)的那一帧就把剩余尾巴吸附到最终位置;若没收到 KeyUp(焦点丢失等),`40ms` 无新移动也会兜底收掉;
7. **硬上限 `trail_max`**:每段动画从开始到结束有时间上限,到点未收敛就直接吸附;
8. **持久输入兜底**:若光标动得太快、dwell 永远等不到,每 `max(dwell*3, 50ms)`(封顶 120ms)强制按最新位置结算一次,不让尾迹冻在原地。

绘制(见 `src/render.rs::Canvas::fill_quad`):四边形拆成两个三角形做逐像素内外测试,颜色 = 尾迹色 × opacity,光标矩形内的像素跳过。动画活跃期间由事件循环定时器(8ms)驱动重绘,静止时 `ControlFlow::Wait` 零唤醒。

## 回看滚动:缓入缓出,输入优先

滚轮 / Shift+PageUp 的回看不是整数行瞬移,而是一段**亚行**动画(实现见 `src/scroll.rs`):

```text
目标行 += 滚动行数,钳制到 [0, scrollback_rows - rows]        # 连发累加,不丢档
时长   = anim(90ms) × √(剩余距离 / 3),封顶 max(200ms)
曲线   = 从静止开始 → cubic ease-in-out                       # 起步慢、中段快、收尾慢
         上一段还在跑 → ease-out 接上                         # 已有速度,不再从 0 加速
每帧 pos 插值 → view = ceil(pos),frac = ceil(pos) - pos
渲染   整屏上移 frac × cell_h 像素                             # 顶部那行只露半截,无接缝
```

按键 / 粘贴时视口要回到底部,这条路径同样有约束:

```text
back_to_bottom(urgent = 光标尾迹已进入连续输入状态):
    时长 = urgent ? back_burst(40ms) : back(90ms),曲线 ease-out
    已经在回底途中且不慢于这次 → 直接返回,不重启动画
    到位后光标本体出现,尾迹自己把剩下的一点位移播完
```

第 2 条是"长按回车"的关键:如果每次按键都重启回底动画,50ms 一次的重启会让视口永远停在半路,看起来就是"松手了屏幕还在回车"。现在回底抢在下一批输出之前完成(`back_burst`),滚动和尾迹各走各的,不再互相拖。回看期间不画尾迹(它属于屏幕底部那个光标,画在上翻的画面上只是残影)。

| 配置 | 默认 | 含义 |
|---|---|---|
| `scroll.anim` | `90` | 一个滚轮档位的平滑动画时长(毫秒);`0` = 关闭(逐行瞬移) |
| `scroll.max` | `200` | 单段动画的硬上限(毫秒) |
| `scroll.back` | `90` | 按键/粘贴后回到底部的时长(毫秒) |
| `scroll.back_burst` | `40` | 长按连续输入时回底的时长(毫秒) |

> 为什么有时看不到动画?两个已修复的坑:(1) 触发门要求光标"停留"若干毫秒,这段时间内若没有新的终端输出,旧实现不会继续出帧,尾迹永远等不到启动 —— 现在 `needs_frames()` 会在等待期持续用 8ms 定时器驱动重绘;(2) 每轴阈值若设为 ≥1,单格移动和普通回车会被直接吸附 —— 本项目默认 `0`,想要 kitty 默认行为可设 `2`。

## 三处复用:窗格内、跨窗格、浮层

`CursorTrail` 在这三个地方是**同一个实例**意义的同一套代码,不是"三个长得像的动画":

| 用途 | 起点 | 落点 | 开关 |
|---|---|---|---|
| 窗格内(默认) | 上一帧的光标格 | 本帧的光标格 | `cursor.trail` |
| 跨窗格切换 | 旧 pane 的光标格 | 新 pane 的光标格 | `pane_focus.trail` / `trail_ms` |
| 浮层打开(搜索栏 / 命令面板) | 终端光标格 | 浮层的输入框 | 同上(共用) |

浮层那条有一个额外的坑:`update` 每帧都会把传入的矩形当成"新目标",而浮层自己在
缩放位移(190ms 的进场动画),若每帧都喂当前帧的输入框位置,`dwell` 会被无限重置,
尾迹**永远不启动**。所以浮层画完之后交给它的是**动画结束时的**输入框位置(恒等变换
下算一遍),尾巴才会正常追过去。第一帧就要算"可见"(`OverlayAnim::visible` 在
`t == 0` 但仍在进场时返回 true)也是同一个道理:否则调用方会以为没东西可画,
顺手把飞行状态清掉。
